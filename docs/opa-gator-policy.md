# OPA Gatekeeper & Gator for Unified Policy Compliance

To standardize governance across AWS, Azure, and GCP in Chiral pattern, transition from cloud-specific linting (cdk-nag or Bicep linter) to unified Policy-as-Code (PaC) engine.

While AWS/Azure tools catch "low-hanging fruit" in development, Open Policy Agent (OPA) / Gatekeeper is industry standard for cross-cloud governance.

## Standardizing with OPA Gatekeeper & Gator

Gator is CLI companion for OPA Gatekeeper. Traditionally for Kubernetes, increasingly used to validate any JSON/YAML-based infrastructure configuration—including Chiral-generated templates.

### 1. Comparison of Compliance Tools

| Feature               | cdk-nag (AWS)            | Bicep Linter (Azure)     | Gator / OPA (Cross-Cloud) |
|-----------------------|--------------------------|--------------------------|---------------------------|
| Primary Focus        | AWS Construct Tree      | ARM/Bicep Templates     | Policy-as-Code (Any JSON/YAML) |
| Logic Language       | TypeScript / Aspects    | Native Bicep Rules      | Rego (Declarative)       |
| Scope                | AWS-specific            | Azure-specific          | Unified/Universal        |
| Dev Loop             | cdk synth               | az bicep build          | gator test               |

### 2. Why Gator/OPA Fits Chiral Pattern

Chiral output is structured artifact (CDK/Bicep/Terraform/Kubernetes YAML). Pass generated artifacts through Gator in CI/CD pipeline.

- **Uniformity**: Write policy in Rego once (e.g., "All storage must be encrypted") and apply to AWS CloudFormation and Azure ARM templates.
- **Shift-Left Validation**: Like testing Bicep with azlocal or az bicep build, run `gator test` against Chiral outputs. Build fails if file violates Rego policies.

### Implementation Strategy for Chiral

Treat governance as first-class citizen of Chiral repo:

- **Define Policies in Rego**: Create `policies/` directory in core Chiral repository. Use standard Rego for organizational guardrails.
- **Artifact Conversion**: Ensure CI pipeline converts CDK/Bicep outputs to common JSON/YAML format for Gator evaluation.
- **CI Enforcement**: Add validation step in GitHub Actions workflow:

```yaml
- name: Run Unified Policy Checks
  run: |
    # Validate all artifacts generated by Chiral against Rego policies
    gator test --filename=dist/aws/ --filename=dist/azure/ --filename=policies/
```

### Is Gator Right for You?

- **Use Gator/OPA if**: Complex multi-cloud compliance requirements (e.g., PCI-DSS, SOC2); avoid writing separate rules per cloud provider.
- **Keep Native Linting if**: Primarily concerned with "infrastructure correctness" (valid SKUs, naming) rather than "policy governance" (security, cost, compliance).
